# 시나리오: 메모 작성

- **우선순위:** P0 (필수)
- **대상 화면:** `http://localhost:3000/` (메모 목록, 새 메모 모달 폼)
- **탐색 일시:** 2026-10-16 (Playwright MCP로 직접 수행하여 확인한 동작 기준)

## 우선순위 근거

메모 앱의 진입 기능이며, 수정/삭제 시나리오가 작성된 메모를 전제로 한다. 서버 액션 → Supabase 저장 → 목록 반영의 전체 경로를 한 번에 검증하므로 가장 먼저 통과해야 한다.

## 목적

새 메모를 제목, 카테고리, 마크다운 내용, 태그와 함께 작성하면 DB에 저장되고 목록 맨 앞에 카드로 표시되는지 검증한다.

## 사전 조건

- 개발 서버가 `http://localhost:3000`에서 실행 중이다.
- `.env.local`에 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`가 설정되어 있다.
- 목록 화면이 로딩을 마친 상태다 (`총 N개의 메모` 문구가 보임).

## 테스트 데이터

| 항목     | 값                                                                    |
| -------- | --------------------------------------------------------------------- |
| 제목     | `E2E 작성 {타임스탬프}` (실제 DB를 공유하므로 매번 고유한 값 사용)    |
| 카테고리 | 업무 (`work`)                                                         |
| 내용     | `# E2E 제목`, `**굵게** 텍스트`, `- 항목 1`, `- 항목 2` (줄바꿈 포함) |
| 태그     | `e2e`                                                                 |

## 단계와 기대 결과

| #   | 단계                                                         | 기대 결과                                                                                                  |
| --- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 1   | 목록 화면을 열고 `총 N개의 메모` 문구에서 현재 개수 N을 기록 | 목록이 로딩을 마치고 카드가 표시된다                                                                       |
| 2   | `새 메모` 버튼 클릭                                          | `새 메모 작성` 모달이 열린다. 마크다운 편집기(툴바 + 입력창 + 프리뷰 나란히)가 보인다                      |
| 3   | 제목 없이 `저장하기` 클릭 (검증 확인)                        | 브라우저 기본 검증 메시지("이 입력란을 작성하세요.")가 뜨고, 모달은 열린 채 유지된다. 목록 개수는 N 그대로 |
| 4   | 제목 입력, 카테고리 `업무` 선택, 내용 입력                   | 입력한 마크다운이 오른쪽 프리뷰에 실시간으로 렌더링된다 (`E2E 제목`이 h1으로 표시)                         |
| 5   | 태그 입력창에 `e2e` 입력 후 Enter                            | `#e2e` 칩이 추가되고 입력창은 비워진다. **Enter로 폼이 제출되지 않는다** (모달 유지)                       |
| 6   | `저장하기` 클릭                                              | 모달이 닫힌다. 에러 배너(`data-testid="error-banner"`)가 나타나지 않는다                                   |
| 7   | 목록에서 방금 만든 카드 확인                                 | 카드가 **목록 맨 앞(첫 번째)** 에 있다. 제목, `업무` 배지, `#e2e` 태그가 표시된다                          |
| 8   | 카드의 내용 미리보기 확인                                    | 마크다운 기호가 제거된 평문(`E2E 제목 굵게 텍스트 항목 1 항목 2`)으로 표시된다                             |
| 9   | `총 N+1개의 메모` 문구 확인                                  | 개수가 정확히 1 증가했다                                                                                   |
| 10  | 페이지 새로고침 후 다시 확인                                 | 카드가 그대로 남아 있다 (DB에 영속화됨)                                                                    |

## 선택자 (탐색 시 확인한 값)

| 대상            | 선택자                                                 |
| --------------- | ------------------------------------------------------ |
| 새 메모 버튼    | `getByRole('button', { name: '새 메모' })`             |
| 제목 / 카테고리 | `#title` / `#category` (`selectOption('업무')`)        |
| 내용 입력창     | `#content` (마크다운 편집기의 textarea)                |
| 태그 입력창     | `getByPlaceholder('태그를 입력하고 Enter를 누르세요')` |
| 저장 버튼       | `getByRole('button', { name: '저장하기' })`            |
| 카드            | `[data-testid="memo-item"]` (제목은 카드 안의 `h3`)    |
| 에러 배너       | `[data-testid="error-banner"]`                         |

## 정리 (Cleanup)

실제 Supabase DB에 저장되므로 테스트 종료 시 작성한 메모를 반드시 삭제한다. (`P0-delete-memo.md`의 삭제 절차 사용, 또는 테스트용 DB 분리)

## 작성 시 주의

- 서버 액션 응답을 기다려야 하므로 고정 대기(`waitForTimeout`) 대신 `expect(locator).toBeVisible()` 같은 자동 대기를 사용한다. 개발 서버 첫 호출은 컴파일로 느릴 수 있다.
- DB에 기존 메모가 있으므로 개수는 절대값(예: 6개)이 아니라 **작성 전후의 증가분**으로 검증한다.
- 태그 칩 `span`은 마크다운 편집기 내부 `span`과 섞이므로 `form` 안에서 텍스트(`#e2e`)로 한정해 찾는다.

## 후속 시나리오 후보 (이번 범위 밖)

- 제목은 있고 내용이 공백뿐일 때 `제목과 내용을 모두 입력해주세요.` alert 표시
- 중복 태그 추가 방지, 태그 칩 삭제
- 모달의 `취소`/`X` 버튼으로 닫을 때 저장되지 않음
