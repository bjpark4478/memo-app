# 시나리오: 메모 수정

- **우선순위:** P1 (중요)
- **대상 화면:** `http://localhost:3000/` (메모 카드, 편집 모달 폼)
- **탐색 일시:** 2026-10-16 (Playwright MCP로 직접 수행하여 확인한 동작 기준)

## 우선순위 근거

작성(P0) 다음으로 자주 쓰는 핵심 기능이다. 데이터가 사라지는 위험은 없어 삭제(P0)보다 낮게 두었지만, 기존 값 채우기, 서버 갱신, 목록 반영(중복 생성 방지)을 함께 확인해야 하므로 P1로 분류한다.

## 목적

기존 메모의 편집 폼이 현재 값으로 채워지고, 제목과 카테고리를 수정해 저장하면 **새 메모가 생기지 않고 기존 카드가 갱신**되는지 검증한다.

## 사전 조건

- 개발 서버가 `http://localhost:3000`에서 실행 중이다.
- 수정 대상 메모가 있다. (`P0-create-memo.md`로 `E2E 수정 {타임스탬프}`, 카테고리 `업무`, 태그 `e2e` 메모를 먼저 만든다. 기존 데이터는 수정하지 않는다.)

## 테스트 데이터

| 항목             | 값                                           |
| ---------------- | -------------------------------------------- |
| 원본 제목        | `E2E 수정 {타임스탬프}`                      |
| 수정 후 제목     | `E2E 수정 {타임스탬프} (수정됨)`             |
| 수정 후 카테고리 | 학습 (`study`) — 원본은 업무 (`work`)        |
| 변경하지 않는 값 | 내용, 태그 (`#e2e`) — 그대로 유지되는지 확인 |

## 단계와 기대 결과

| #   | 단계                                                     | 기대 결과                                                                                                       |
| --- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 1   | 목록에서 대상 카드의 `총 N개의 메모` 개수 N을 기록       | —                                                                                                               |
| 2   | 대상 카드의 편집 아이콘(`button[title="편집"]`) 클릭     | 상세 모달이 **열리지 않고**, `메모 편집` 모달만 열린다 (카드 클릭 이벤트 전파 차단)                             |
| 3   | 폼 값 확인                                               | 제목 `E2E 수정 …`, 카테고리 `work`, 내용(마크다운 원문), 태그 `#e2e`가 채워져 있다. 제출 버튼 문구는 `수정하기` |
| 4   | 제목을 `… (수정됨)`으로 변경, 카테고리를 `학습`으로 변경 | 프리뷰/입력값이 즉시 반영된다                                                                                   |
| 5   | `수정하기` 클릭                                          | 모달이 닫힌다. 에러 배너가 나타나지 않는다                                                                      |
| 6   | 목록에서 카드 확인                                       | 제목이 `… (수정됨)`, 배지가 `학습`으로 바뀐다. 해당 제목의 카드는 **정확히 1개**(중복 없음)                     |
| 7   | `총 N개의 메모` 문구 확인                                | 개수가 N 그대로다 (증가하지 않음)                                                                               |
| 8   | 카드의 내용 미리보기, 태그 확인                          | 변경하지 않은 내용과 `#e2e` 태그는 그대로 유지된다                                                              |
| 9   | 페이지 새로고침 후 다시 확인                             | 수정된 제목과 카테고리가 유지된다 (DB에 반영됨)                                                                 |

## 선택자 (탐색 시 확인한 값)

| 대상            | 선택자                                            |
| --------------- | ------------------------------------------------- |
| 대상 카드       | `[data-testid="memo-item"]` 중 `h3` 텍스트로 필터 |
| 편집 아이콘     | 카드 안 `button[title="편집"]`                    |
| 편집 모달 제목  | `h2` 텍스트 `메모 편집`                           |
| 제목 / 카테고리 | `#title` / `#category`                            |
| 수정 버튼       | `getByRole('button', { name: '수정하기' })`       |

## 정리 (Cleanup)

수정한 테스트 메모를 삭제한다. (`P0-delete-memo.md` 절차)

## 작성 시 주의

- 카드를 찾을 때 제목이 바뀌므로, 수정 전/후 제목 locator를 구분하거나 `data-testid`에 의존하지 않고 고유 접두사(`E2E 수정 {타임스탬프}`)로 찾는다.
- 수정 후 정렬은 **작성일(created_at) 내림차순**이라, 수정해도 카드 위치는 바뀌지 않는다. 위치로 검증하지 말고 제목/배지로 검증한다.
- 서버 액션 응답 대기는 자동 대기를 사용한다.

## 후속 시나리오 후보 (이번 범위 밖)

- 상세 모달(카드 클릭)의 `편집` 버튼에서 편집 폼으로 이어지는 흐름
- 내용 수정 시 기존 AI 요약이 무효화되는지 (DB `memo_summaries.source_updated_at` 비교)
- 편집 중 `취소` 시 값이 변경되지 않음
